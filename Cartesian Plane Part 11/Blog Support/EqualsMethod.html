Important note: This page is about the Java equals(Object) method, and we're going to stick to that. But we can't mention equals without referring to the equals and hashCode contract. This states that if you override either equals or hashCode, you must override the other as well.

Java equals Method

The equals method is declared in the Object class. Functionally, it's not very useful. It's equivalent to this: 

public boolean equals( Object object )
{
    if ( this == object )
        return true;
    else
        return false;
}

In other words, Object.equals(Object) judges two objects to be equal if they are the same object. This is not typically very helpful. For example, I can have two different string objects, and if they both have the value "cat" we would normally consider them equal, even if Object.equals(Object) does not.

Consider the following class: 

public class EqualsDemo1
{
    private final String    alpha;
    private final String    beta;
    
    public EqualsDemo1( String alpha, String beta )
    {
        this.alpha = alpha;
        this.beta = beta;
    }
	...
}

In the above example, let's say that we would like an EqualsDemo1 object to be equal to another object if:

  1. The other object is non-null;
  2. The other object is type EqualsDemo1;
  3. The objects' respective alpha fields are equal; and
  4. The objects' respective beta fields are equal.

Of course, now we need to ask what it means for the alpha and/or beta fields to be equal? The easiest thing is to ask if: this.alpha.equals(otherObject.alpha). Unless this.alpha is null, in which case it's equal to otherObject.alpha only if otherObject.alpha is also null.

The equals Contract

When overriding equals you must make sure that your implementation meets the following requirements.

  1. Your implementation must be reflexive; obj.equals(obj) must be true for any non-null obj.
  2. Your implementation must be symmetric; if obj1.equals(obj2) is true, obj2.equals(obj1) must be true; if obj1.equals(obj2) is false, obj2.equals(obj1) must be false.
  3. Your implementation must be transitive; if obj1.equals(obj2) is true, and obj2.equals(obj3) is true, then obj1.equals(obj3) must be true.
  4. Your implementation must be consistent; the result of obj1.equals(obj2) must be the same every time you invoke it (assuming no information used in the comparison is modified).
  5. Your implementation must handle null; the result of obj1.equals(null) must always be false.

public class EqualsDemo1

    ...
    @Override
    public int hashCode()
    {
        return Objects.hash(alpha, beta);
    }

    @Override
    public boolean equals( Object other )
    {
        boolean result  = false;
        if ( this == other  )
            result = true;
        else if (other == null)
            result = false;
        else if ( !(other instanceof EqualsDemo1) )
            result = false;
        else
        {
            EqualsDemo1  that   = (EqualsDemo1)other ;
            if ( this.alpha != null && !this.alpha.equals( that.alpha ) )
                result = false;
            else if ( this.alpha == null  && that.alpha != null )
                result = false;
            else if ( this.beta != null && !this.beta.equals( that.beta ) )
                result = false;
            else if ( this.beta == null && that.beta != null )
                result = false;
            else
                result = true;
        }
        return result;
    }    
}

Some notes about the above code:

  • Lines 4-8: Since we're overriding equals we must also override hashCode.
  • Lines 14-15: Testing to see if this and other are the same object is not strictly necessary; it's an optimization.
  • Lines 16-19: The other object isn't equal to this if it's null, or if it's the wrong class.
  • Lines 23-24: if this.alpha isn't null, we can ask if this.alpha.equals(that.alpha).
  • Lines 25-26: if this.alpha is null, we can ask if that.alpha is also null.
  • Lines 27-30: go through all the null checking and .equals checking again for the beta field.

A couple of more remarks about the equals method itself. You may have noticed that lines 23 through 30 in the above example are rather painful. And for a class that has more than two fields it will get very tedious. Note also, however, that the pattern is going to be the same when testing any pair of non-primitive values. The Java utility class Objects has an equals(Object,Object) method that executes the same testing pattern. Lines 23-30 of the above example can be changed to lines 14-17 of the sample below.

A second modification we can make to the the equals method comes from a feature introduced in Java 15 and made permanent in Java 16: Pattern Matching for instanceof. Using this technique, lines 18-22 of the above can be changed to: 

else if ( other instanceof EqualsDemo2 that )

JUnit Test for equals

The test for an equals method is tedious. Let's write a test for the equals method in EqualsDemo1.

I will start by declaring two different values for each field in the class: 

@Test
void testEquals()
{
    String      alpha1  = "alpha 1";
    String      alpha2  = "alpha 2";
    String      beta1   = "beta 1";
    String      beta2   = "beta 2";
    // ...
}

Now declare two objects. Their initial values should be equal. 

@Test
void testEquals()
{
    // ...
    EqualsDemo1 objA    = new EqualsDemo1( alpha1, beta1 );
    EqualsDemo1 objB    = new EqualsDemo1( alpha1, beta1 );
    // ...
}

Test one object against itself and verify that the result is true; test the object against an object of a different class and verify that the result is false; test the object against null and verify that the result is false; 

@Test
void testEquals()
{
    // ...
    assertEquals( objA, objA );
    assertNotEquals( objA, new Object() );
    assertNotEquals( objA, null );
    // ...
}

Verify that the two objects are equal, and that their hashcodes are equal; verify symmetry by reversing the order of the test. 

@Test
void testEquals()
{
    // ...
    assertEquals( objA, objB );
    assertEquals( objB, objA );
    assertEquals( objA.hashCode(), objB.hashCode() );

A final word about testing equals/hashCode. And I have to admit this bothers me a little because it goes beyond testing requirements. We'll begin with this observation:

It is possible for two unequal objects to have equal hashcodes. Given a large enough data sample, it is even expected. However...

... given the limited data sample in an equals method test if we find unequal objects with equal hashcodes it is likely that there is something wrong with the hash algorithm.

Reliable hash algorithms are crucial in many contexts, so much so that many programmers choose to verify in an equals/hashCode unit test that unequal objects have unequal hashcodes. I'll finish up this discussion with a separate test that includes this validation.

@Test
public void verifyHash()
{
    // Verify the reliability of the hashCode method.
    // Unequal objects are not required to have unequal hashcodes,
    // but, in this limited test, if they don't it may indicate
    // a problem with the hash algorithm and should be
    // investigated.
    String      alpha1  = "alpha 1";
    String      alpha2  = "alpha 2";
    String      beta1   = "beta 1";
    String      beta2   = "beta 2";
    
    EqualsDemo2 objA    = new EqualsDemo2( alpha1, beta1 );
    EqualsDemo2 objB    = new EqualsDemo2( alpha1, beta2 );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB = new EqualsDemo2( alpha2, beta1 );
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB = new EqualsDemo2( alpha2, beta2 );
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB    = new EqualsDemo2( alpha1, null );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB    = new EqualsDemo2( alpha2, null );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB    = new EqualsDemo2( null, beta1 );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB    = new EqualsDemo2( null, beta2 );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
    
    objB    = new EqualsDemo2( null, null );        
    assertNotEquals( objA, objB );
    assertNotEquals( objA.hashCode(), objB.hashCode() );
}
